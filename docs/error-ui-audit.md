# Error UI audit — 2026-09-12

This is a static audit of error, failed-load, unavailable and not-found displays
under `src/pages` and `src/components`, traced back to their operation owners.
Browser fault injection and targeted hook diagnostics validate representative
recovery paths; they do not simulate every listed operation or sign real events.

The contract is [error recovery](error-recovery.md). A retry must restart the
failed operation, not merely rerender its error. Read failures must not masquerade
as a successfully loaded empty list or prove that a Git object is absent.

## Existing manual actions and deliberate exceptions

| Surface                                                                                                                                                                                 | Audit decision                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication (`LoginDialog`, `AuthModal`, `SignupDialog`, `NwcQrConnect`)                                                                                                             | Keep explicit connect/login/signup actions and correction guidance. Never attach an automatic retry to a signer or wallet connection.                                                                                                                                                                                                                                                                |
| Private discovery (`Dashboard`, `Settings`, `RepoLayout`)                                                                                                                               | Existing visible retry/decryption and service-review actions remain manual. Private Git admission errors offer a manual restart of the repository view (reruns its admission checks without reloading the app) and link to service settings; missing credentials, unannounced roots and account rejection need login/configuration/access correction. Do not bypass verified private-root admission. |
| Repository creation (`CreateRepoDialog`)                                                                                                                                                | Existing Retry Push and editable creation form retain the known transaction state; no new automatic mutation attempt.                                                                                                                                                                                                                                                                                |
| Repository edit/repair/delete (`RepoSettingsPage`, `RepoAdvancedRepairPage`, `RepoAboutPanel`)                                                                                          | Preserve editable values, validation messages and explicit save/publish/delete controls. Unsupported membership operations retain their explanation.                                                                                                                                                                                                                                                 |
| Comments, cover notes, subjects, labels and statuses (`ReplyBox`, `InlineCommentThread`, `CoverNoteBox`, `EditSubjectInline`, `ManageLabels`, `StatusDropdownBadge`, `CreateIssueForm`) | Existing user-triggered controls remain available after failure. Retain partial-success handling; never replay a successful comment just to retry a failed status change.                                                                                                                                                                                                                            |
| Social / event actions (`UserPage`, `FollowRepoButton`, `StarButton`, `ReactionsBar`, `EventCardActions`, `EventThreadComponents`, `ThreadTree`, `PushEventComponents`)                 | Keep explicit action controls and existing publication delivery handling. Console-only diagnostics are not new user-facing errors.                                                                                                                                                                                                                                                                   |
| Merge (`MergePanel`)                                                                                                                                                                    | Existing Recheck / manual merge and delivery controls retained. A conflict is a result requiring correction, not an automatic retry.                                                                                                                                                                                                                                                                 |
| CI (`CIChecksPanel`, `CICoordinatorPanel`, `CISecretsDialog`)                                                                                                                           | Existing Retry workflow / service-request / secret-save controls remain explicit signing actions. A completed failing CI job is not a failed UI load.                                                                                                                                                                                                                                                |
| Release publishing (`CreateReleaseDialog`, `CreateSoftwareApplicationDialog`, `LinkSoftwareApplicationDialog`)                                                                          | Existing forms keep their errors and explicit submit actions. Do not replay partially completed uploads/publications automatically.                                                                                                                                                                                                                                                                  |
| Payment (`ZapModal`)                                                                                                                                                                    | Existing invoice/payment error and retry controls remain manual, preserving wallet-specific retry eligibility.                                                                                                                                                                                                                                                                                       |
| Outbox (`OutboxPanel`, `OutboxStatusStrip`)                                                                                                                                             | Existing delivery scheduling is separate from UI recovery. Made the per-relay Retry now label visible instead of icon-only. Existing signed-event delivery does not request a new signature; no new publication automation added.                                                                                                                                                                    |
| Application crash (`ErrorBoundary`)                                                                                                                                                     | Existing Try again / reload recovery remains manual, apart from its existing once-only fresh-asset reload. Do not replay component mutations.                                                                                                                                                                                                                                                        |
| Validation / deliberate absence (`NotFound`, `IncompatibleProtocolError`, private-feature-unavailable, form validation, unsupported QR/renderer states)                                 | Keep correction, navigation or capability explanations. Invalid input and confirmed deletion are not transient failures.                                                                                                                                                                                                                                                                             |
| Diagnostics (`RelayCoveragePopover`, relay status rows, `RefSelector`, `GitServerStatusIcon`, CI capability badges)                                                                     | These explain an owning operation's state. Reuse that owner's recovery; do not create per-badge timers or signing requests.                                                                                                                                                                                                                                                                          |
